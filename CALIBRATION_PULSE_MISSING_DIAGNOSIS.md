## 2. Root Cause Analysis

### ❌ **PROBLEM 1: Calibration Pulse Duration Too Short (600ms)**

**ESP32 Calibration Pulse Timing:**
- **Head**: 200ms flat baseline before pulse
- **Pulse**: 200ms square wave at 1mV
- **Tail**: 200ms flat baseline after pulse
- **Total**: 600ms (300 samples at 500Hz)

**Current Display Buffer:**
- Buffer holds **25 seconds** (12,500 samples at 500Hz)
- When ECG viewer opens, buffer is typically **empty** or has very few samples
- Calibration pulse (300 samples) arrives first
- **By the time significant ECG data arrives**, the 300-sample calibration pulse is **drowned out** by 12,000+ samples of real ECG

**Math:**
```
Calibration: 300 samples @ start of buffer
ECG data arriving at: 500 samples/second

After 24 seconds of ECG data:
- Buffer contains: 12,000 ECG samples + 300 calibration samples = 12,300 total
- Calibration is only 2.4% of visible waveform (300/12500)
- Typewriter mode shows LAST 6947 samples → calibration scrolled off left edge
```

### ❌ **PROBLEM 2: No Frontend Code to Request Calibration on ECG Viewer Open**

Looking at [useECGViewer.ts](hospital-display-app/src/hooks/useECGViewer.ts), the code:
1. ✅ Initializes blank canvas (clears cache)
2. ✅ Subscribes to WebSocket for patient
3. ❌ **DOES NOT send `triggerCalibration: true` flag**

**Current Code** ([useECGViewer.ts:246-258](hospital-display-app/src/hooks/useECGViewer.ts#L246-L258)):
```typescript
// Subscribe to this patient's data
webSocketService.subscribe(patient.id, {
  onVitalsUpdate: (data) => { /* ... */ },
  onWaveformUpdate: (data) => { /* ... */ },
  onAlert: (data) => { /* ... */ }
});
```

**Missing:**
```typescript
// ❌ MISSING: Trigger calibration pulse on ECG viewer open
webSocketService.triggerCalibration(patient.id);
```

### ❌ **PROBLEM 3: Frontend-Generated Calibration Code Was Removed**

**Before** ([ECGViewerContainer.tsx:54-71](hospital-display-app/src/components/ECGViewer/ECGViewerContainer.tsx#L54-L71)):

**The comment says** "watch sends real calibration via waveform stream" but:
1. Frontend never requests calibration from watch ❌
2. Even if watch sends it, it scrolls off screen due to PROBLEM 1 ❌

## 3. Why Calibration Pulse Disappeared

### Timeline:
1. **Before**: Frontend generated fake calibration pulse (200ms head + 200ms pulse + 200ms tail) and displayed it
2. **ESP32 v5.2+**: Added real calibration pulse generation in `PhysiologicalSimulator`
3. **Frontend refactor**: Removed frontend calibration generation, expecting ESP32 to send it
4. **BUT**: Frontend never sends `triggerCalibration: true` to backend WebSocket
5. **AND**: 25-second buffer drowns out 0.6-second calibration pulse

### Result:
- User opens ECG viewer → blank canvas ✅
- No calibration pulse requested from ESP32 ❌
- Real ECG data starts flowing immediately
- User never sees calibration pulse ❌

## 4. Solutions (Multiple Options)

### **Option A: Fix Frontend to Request Calibration** (Recommended)

**Fix 1:** Add calibration trigger in [useECGViewer.ts](hospital-display-app/src/hooks/useECGViewer.ts):
```typescript
useEffect(() => {
  // Subscribe to patient with calibration trigger
  webSocketService.subscribe(patient.id, {
    onVitalsUpdate: handleVitalsUpdate,
    onWaveformUpdate: handleWaveformUpdate,
    onAlert: handleAlert,
    triggerCalibration: true  // ✅ NEW: Request calibration on ECG viewer open
  });

  return () => {
    webSocketService.unsubscribe(patient.id);
  };
}, [patient.id]);
```

**Fix 2:** Update [WebSocketService.ts](hospital-display-app/src/services/WebSocketService.ts) `subscribe()` to pass `triggerCalibration` flag:
```typescript
subscribe(patientId: string, callbacks: {
  onVitalsUpdate?: Function;
  onWaveformUpdate?: Function;
  onAlert?: Function;
  triggerCalibration?: boolean;  // ✅ NEW
}) {
  this.send({
    type: 'subscribePatient',
    patientId: patientId,
    triggerCalibration: callbacks.triggerCalibration || false  // ✅ NEW
  });
  // ... rest of code
}
```

**Fix 3:** Backend already supports this ([websocket.py:96](hospital-backend/app/api/v1/websocket.py#L96)):
```python

```

**Fix 4:** ESP32 already supports this ([esp32_hospital_watch_complete.ino:905-938](esp32_hospital_watch_complete/esp32_hospital_watch_complete.ino#L905-L938)):
