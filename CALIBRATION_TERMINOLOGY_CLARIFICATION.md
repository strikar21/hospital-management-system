# Calibration Terminology - Two Different Things

## The Confusion

The system has TWO different types of "calibration":

### 1. **Calibration Pulse** (ECG/EEG Visual Reference)
- 1mV square wave displayed on waveforms
- Visual reference for amplitude measurement
- Standard medical practice (like the pulse at start of ECG printouts)
- Generated by simulator
- Temporary (3 seconds)
- Triggered when opening ECG viewer

### 2. **Device Calibration** (Hardware Sensor Calibration)
- Actual sensor calibration (temperature, SpO2, etc.)
- Part of device maintenance system
- Generates alerts when overdue
- Affects measurement accuracy
- Stored in database
- Scheduled/periodic

## Current Code Issues

### Backend Code Uses Confusing Names:

**File:** `websocket.py:261`
```python
async def _triggerDeviceCalibration(deviceId: str, patientId: str) -> None:
    """Send MQTT calibration command to device"""
```

**This function name is WRONG!** It's not triggering device calibration, it's triggering a **calibration pulse**.

---

### ESP32 Code Is Correct:

**File:** `esp32_hospital_watch_complete.ino:944-945`
```cpp
// ✅ Trigger physiological simulator calibration pulse (3000ms: 1000ms head + 1000ms pulse + 1000ms tail)
simulator.startCalibrationPulse();
```

**File:** `esp32_hospital_watch_complete.ino:970`
```cpp
sendCommandAck(commandId, true, "Calibration pulse sent to all ECG leads (3000ms)");
```

ESP32 correctly calls it **"calibration pulse"**.

---

### Frontend Code Is Ambiguous:

**File:** `WebSocketService.ts:259`
```typescript
console.log(`🔧 Calibration requested for patient: ${patientId}`);
```

Should be: `🔧 Calibration pulse requested for patient: ${patientId}`

## Recommended Terminology Changes

### Backend Changes Needed:

1. **Rename function:**
   ```python
   # OLD
   async def _triggerDeviceCalibration(deviceId: str, patientId: str) -> None:

   # NEW
   async def _triggerCalibrationPulse(deviceId: str, patientId: str) -> None:
   ```

2. **Update comments:**
   ```python
   # OLD
   # ✅ NEW: ECG viewer can request calibration

   # NEW
   # ✅ NEW: ECG viewer can request calibration pulse
   ```

3. **Update log messages:**
   ```python
   # OLD
   logger.info(f"🔧 Calibration triggered for device {deviceId}")

   # NEW
   logger.info(f"🔧 Calibration pulse triggered for device {deviceId}")
   ```

4. **Update MQTT command:**
   ```python
   # Current command type
   command = {
       'command': 'calibrate',  # Could be confused with device calibration
       'commandId': commandId,
       # ...
   }

   # Consider changing to
   command = {
       'command': 'calibrationPulse',  # More specific
       'commandId': commandId,
       # ...
   }
   ```

## Device Calibration System (Separate Feature)

This is a DIFFERENT feature that already exists:

**Files:**
- `hospital-backend/app/services/calibration_service.py`
- `hospital-backend/app/services/calibration_monitor.py`
- `hospital-backend/migrations/012_device_maintenance_infrastructure.sql`

**Database Tables:**
- `device_maintenance` - Tracks calibration schedules
- `calibration_alerts` - Alerts when calibration is overdue

**This is for actual hardware sensor calibration, not the visual waveform pulse.**

---

## Summary

**Current Problem:** The term "calibration" is overloaded and means two different things.

**Solution:**
- Always use **"calibration pulse"** for the ECG/EEG visual reference square wave
- Always use **"device calibration"** for hardware sensor calibration
- Update code to consistently use these terms

**Priority:** This is a P2 refactoring - should be done for clarity but doesn't affect functionality.

**Current Issue:** The calibration pulse feature isn't working, but naming confusion makes debugging harder.
